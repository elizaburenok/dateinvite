# Приглашение в места

Личный продукт на 1:1: хост собирает библиотеку мест через Telegram-бота, складывает
3–5 мест в конверт и отправляет одному человеку ссылку. Гость открывает её в браузере
без установки и аккаунта, выбирает одно место и отвечает — хосту приходит уведомление
в бота.

ТЗ — [`tz-invite-app.md`](tz-invite-app.md).

## Из чего состоит

```
packages/
  shared/    типы и zod-схемы контракта §8 + токены дизайна (единственный источник правды)
  api/       Fastify + SQLite + бот на grammY + резолвер мест — один процесс
  miniapp/   Mini App хоста: библиотека, инбокс, сборка конверта, «мои конверты»
  guest/     страница-конверт по публичному токену
data/        invite.db и кеш фото (в git не попадает)
deploy/      Caddyfile, systemd-юнит, .env.example
```

Бэкенд раздаёт и API, и оба фронтенда, поэтому в проде перед ним стоит один Caddy
как TLS-прокси, без разводки по путям.

| Путь | Что отдаёт |
|---|---|
| `/api/*` | host API (по `initData`) и публичные роуты конверта (по токену) |
| `/bot/webhook/<secret>` | вебхук Telegram |
| `/media/*` | кешированные фото мест |
| `/app/` | Mini App |
| `/i/<token>` | страница-конверт |

## Как резолвятся места

Ветки по §7 ТЗ, все — без платных ключей:

| Что прислали | Что делаем |
|---|---|
| Ссылка Яндекс.Карт | разворачиваем редирект, берём координаты из параметров URL, обогащаем через OSM |
| Геометка или venue | reverse-геокодинг через OSM |
| Текст без гео | эвристика достаёт название → поиск в OSM → **1–3 кандидата хосту на подтверждение** |
| Ничего не разобрали | честно говорим об этом, место не создаём |

Два решения, принятых по результатам проверки живых источников:

- **Официальный Yandex Geosearch API не используется.** Он прямо запрещает сохранять
  полученные данные, а весь продукт стоит на снапшоте (§3): конверт обязан пережить
  удаление исходного поста. Плюс ключ выдаётся вручную и платно.
- **HTML страницы организации не парсится.** Это SPA-оболочка: `<title>` и og-теги
  дженериковые, координаты в разметке — центр Москвы, а не организации. От Яндекса
  законно берутся только координаты из URL и сам URL как «открыть в Картах».

Название, адрес, район и категория приезжают из **OpenStreetMap Nominatim** — его
лицензия ODbL разрешает кеширование. Взамен обязательны: не чаще одного запроса
в секунду, содержательный `NOMINATIM_USER_AGENT` с контактом, кеш (таблица `geo_cache`)
и атрибуция «© участники OpenStreetMap» в интерфейсе. Всё это уже сделано — не убирайте.

Фото берётся из самого Telegram-поста через Bot API и кешируется в `data/media`.
Фото с Яндекс.Карт не используются. Когда фото нет, карточка рисует спокойную
заливку, выведенную из самого места.

## Локальная разработка

```bash
npm install
npm run build -w @invite/shared
```

Поднять API и наполнить базу примером:

```bash
PUBLIC_BASE_URL=http://localhost:3000 npm run seed:dev -w @invite/api
```

```bash
PUBLIC_BASE_URL=http://localhost:3000 npm run dev:api
```

Гость-страница (порт 5174) — открывать по адресу `/i/<token>`, токен печатает `seed:dev`:

```bash
npm run dev:guest
```

Mini App вне Telegram не получает `initData`, поэтому её подставляют вручную.
Запустите API с любым непустым `BOT_TOKEN` и `DEV_SKIP_BOT=1` (так API умеет
проверять подпись, но не ходит в Telegram), затем:

```bash
BOT_TOKEN=<тот же токен> node packages/api/dist/scripts/dev-init-data.js
```

Результат положите в `packages/miniapp/.env.local` как `VITE_DEV_INIT_DATA=...` и
запустите `npm run dev:miniapp` (порт 5175, адрес `/app/`).

## Что нужно от хостинга

Приложение — **один постоянно работающий процесс с диском**. Это не прихоть, а следствие
принципа снапшота: SQLite и кеш фото лежат файлами, и они обязаны переживать перезапуск.

Отсюда жёсткое требование: **бессерверные платформы (Vercel, Netlify, Cloudflare Workers)
не подходят.** Они поднимают функцию на время запроса и гасят её, диск между вызовами
не сохраняется — база и фото обнулялись бы. Подходят Railway, Fly.io, Render с диском,
любой VPS. Фронтенды туда класть отдельно не нужно: их раздаёт тот же процесс.

Нужен именно **https**: Telegram не открывает Mini App и не шлёт вебхуки по http.
Без https приложение само переходит на long polling — бот работает, Mini App нет.

## Деплой через Docker (Railway, Fly.io, любой VPS)

В корне лежит `Dockerfile`. Единственное, что нужно помнить: **подключить постоянный том
к `/app/data`**, иначе при первом же перезапуске исчезнут все места и конверты.

1. Создайте проект из репозитория — платформа сама найдёт `Dockerfile`.
2. Подключите том (volume) на `/app/data`.
3. Задайте переменные окружения из `deploy/.env.example`. `PUBLIC_BASE_URL` — тот адрес,
   который выдала платформа, обязательно с `https://`.
4. После первого деплоя приложение само поставит вебхук и кнопку меню бота.
5. У @BotFather задайте Mini App на `https://<домен>/app/`.

Если платформа подставляет свой порт — конфиг читает `PORT`, ничего менять не надо.

## Деплой на свой сервер без Docker

1. Скопируйте `deploy/.env.example` в `.env` рядом с `package.json` и заполните
   `BOT_TOKEN`, `PUBLIC_BASE_URL` (обязательно `https`), `WEBHOOK_SECRET`
   (`openssl rand -hex 24`) и `NOMINATIM_USER_AGENT` со своей почтой.
2. `npm ci && npm run build`
3. Положите `deploy/invite-api.service` в `/etc/systemd/system/`, подставьте свои пути
   и запустите: `systemctl enable --now invite-api`.
4. Пропишите домен в `deploy/Caddyfile` и перезапустите Caddy — сертификат он получит сам.
5. Вебхук приложение ставит само при старте, если `PUBLIC_BASE_URL` начинается с `https://`.
6. У @BotFather задайте Mini App на `https://<домен>/app/`.

## Про туннели для локальной проверки

Показать приложение живому человеку с локальной машины можно через туннель
(`cloudflared`, `ngrok`), но у обоих есть подвохи:

- `cloudflared` ходит через порт **7844**, который часто закрыт в корпоративных сетях;
- бесплатные тарифы `ngrok` и `pinggy` подменяют браузерную страницу собственной
  заставкой — вместо конверта и Mini App гость увидит предупреждение;
- временный адрес меняется при каждом перезапуске, и уже разосланные ссылки на конверты
  перестают открываться.

Для разовой проверки это годится, для чего-то большего — берите нормальный домен.

## Что сознательно не сделано

- **LLM-разбор текстовых постов** (§7). Заменён эвристикой: она ничего не выдумывает,
  а всё найденное всё равно уходит хосту на подтверждение, поэтому приёмочный критерий
  §12 выполняется. Точка расширения — интерфейс `NameExtractor` в
  `packages/api/src/resolver/textCandidates.ts`: LLM-реализацию можно добавить рядом,
  не трогая остальной резолвер.
- Всё из §15 ТЗ: групповое голосование, события без локации, шаблоны конвертов, аналитика.
